# СППР «пучок Леонтьева на ГРС» — программа (КТ5)

Программа готовит для главного инженера рекомендацию по конструкции и режиму узла редуцирования ГРС с пучком труб Леонтьева (RU 2162190). Сама она ничего не регулирует. Если данных не хватает, она предлагает адресный расчёт Fluent.

## Запуск

```
python sppr.py cards\<карточка>.json            # рекомендация + запись в журнал решений
python sppr.py cards\<карточка>.json --no-journal
```

Результат: `runs\program\<карточка>_рекомендация.md`.

Запись журнала: `runs\journal\Журнал_решений.md`. Поле «решение ЛПР» в ней остаётся «ожидает», его заполняет главный инженер.

## Шаги (по плану 18.10)

1. **Карточка задачи (п. 2.1).**
   - Сценарий f: давление и температура газа в магистрали, отпуск.
   - Задание x0: давление потребителя, T_min, требуемый выход СПГ.
   - Проектные варианты u_п: вид конструкции, t/d, L, место подогревателя.
   - Режимные u_р: перепад ДЗВ, число труб.
   - Параметры ЛПР: δ в K и ε_N в кВт.
   - Необязательно: u0 — существующая конструкция и режим; список сценариев для режимной карты.
2. **Прогноз ± σ.**
   - ГП по точкам CFD: эффект, Q, расходы СВЗ и ДЗВ.
   - Классификатор CatBoost: p «рабочий» и порог p_hi. Порог подбирается вложенной перекрёстной проверкой при каждом запуске.
3. **Баланс станции (`dataset\grs_balance2.py`).**
   - Мощность подогревателя (σ по Q) и выход СПГ.
   - Перебор числа труб от 1 до n_rule = целая часть (расход станции / расход трубы).
4. **Правила П1–П3 (п. 2.2)** — статусы Δ1 «выдать», Δ2 «досчитать», Δ3 «вернуть задачу».
   - Паспорт Ω: 0,2 ≤ m ≤ 0,96, факторы в границах данных.
   - «Не рекомендовано» — если ни один вариант в Ω не выполняет задания.
5. **Режимный и проектный ресурс (п. 2.1, 4.4).** Режимная карта (п. 4.5).
6. **Запись в журнал решений (п. 4.7).**

## Ограничения

- Варианты по патентам (накатка, диффузор, три потока) пока дают только П1 «не рассчитан». CFD накатки есть только в одном режиме (A9_19).
- Место подогревателя «до сопел» допустимо, пока подогрев СВЗ не выходит за рассчитанный диапазон (до ~20 K). Если выходит — правило П1.

## Подтвердить → посчитать → статус обновился (29.10.2026)

```
python sppr.py cards\<карточка>.json --confirm
```

Команда ставит расчёт в очередь и сама Fluent не запускает (30.10.2026): текущий расчёт не прерывается, второй Fluent не стартует.
Что считается: при Δ2 «досчитать» — предложенный вариант; при П1 «край данных» — серия за краем (новое значение фактора, 2–3 режима перепада ДЗВ).
1. записывает прогноз до расчёта (`runs\journal\confirm_forecasts.json`, теги CFnn, статус «в очереди») и запись «поставлено в очередь» в журнал решений;
2. `dataset\confirm_runner.py` на своём месте в очереди считает точки: посчитанная геометрия — продолжение от ближайшего кейса, новая t/d при той же L — перенос поля;
3. сошедшиеся точки идут в обучение; модели переобучаются, задача решается заново;
4. в журнал решений — запись «было → прогноз → Fluent → разница → новый статус и лучший вариант».

## Лучшее на границе данных (30.10.2026)

Если лучший вариант лежит на краю посчитанного диапазона по t/d, L или перепаду ДЗВ, статус — П1 «край данных»: программа пишет «лучшее на границе данных» и предлагает серию за краем.
Физический край расчёта не требует: по L с текущим соплом длиннее 660 мм нельзя (1D: сверхзвук не удерживается, `runs\program\край_задачи2_1D.md`). Сопло и накатка — после их ввода как факторов модели.
